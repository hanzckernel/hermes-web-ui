Phase 03 hardens Group Chat channel visibility after final review. Agent interrupt requests now require the caller to see the active context-status visibility envelope before cancelling private work, and ready status reuses the stored active envelope instead of trusting client-supplied public fields. Streaming ownership is keyed by room plus stream id and stream starts are accepted only from verified agent sockets, preventing human assistant-stream spoofing and cross-room stream replay while still allowing independent rooms to use the same stream id safely. Human sockets also cannot reserve a room agent display name or persist assistant/tool metadata, add-agent routes persist room-agent identity before runtime join and reject human/agent display-name collisions before runtime connection, and the client classifies agents by stable agent id rather than display name. Actor-scoped agent context and token refreshes are bounded to public plus the active reply visibility envelope, including thread id, and bridge session ids include the visibility envelope so private bridge-side state is not reused by later public turns. Realtime context-status identity is derived from the connected agent socket instead of a client-supplied display name. Non-string audience payloads are preserved through a shared audience helper instead of being coerced to room-public, object-form bridge audiences share the same fingerprint as equivalent actor arrays, bridge session ids keep the visibility fingerprint outside the truncated prefix so long profile/name values cannot erase envelope isolation, and socket actor identities are keyed by room so one socket joined to multiple rooms cannot authorize with another room's actor.

Phase 04 adds the scoped context builder layer on top of that visibility baseline: actor-scoped context now uses a deterministic contextKey, stores compressed summaries in gc_scoped_context_snapshots rather than the legacy room-wide gc_context_snapshots key, and sends the same scoped projection to token estimation and model input. The projection includes actor-visible messages, current channel/thread/visibility/scope, allowed actions, and actor private facts.

Phase 05 is intentionally not shipped as a full handoff/publish/artifact/approval transfer protocol in this stack. The optional transfer-card slice only supports explicit fenced group-chat-transfer/gc-transfer JSON blocks for private fact create/revoke, strips raw transfer blocks from stored/displayed message content and metadata/realtime side channels, keeps private-fact content out of normal message metadata and normal realtime message payloads, and updates the scoped private-fact projection used by Phase 04 prompts. It does not emit a general transfer.card realtime event; full handoff, publish request, artifact reference, approval-card UI, structured transfer events, and persisted transfer/artifact tables are deferred to a later dedicated PR. Socket message, stream, typing, context-status, and token-total writes now require the actor's message.write capability before channel visibility checks, and actor reads require message.read before REST/context/realtime visibility checks, so disabled actors cannot bypass the capability model. Ponytail review trims the user-facing debug surfaces and keeps this stack scoped to the internal channel store plus minimal server private-fact transfer cards.
